Why not live: the rule acts two hours after upload and this suite posts none of its documents on chain; C44-mark-only shows a verified one is still served at 52 minutes.
- NOT RUN live: C9-registry-code: the relay checks the registry's code against the deploy record and answers every relay 503 registry_mismatch, moving no counter, when the address holds other code or none. Proven by packages/server/test/relay.test.ts: "answers every relay 503 registry_mismatch and moves no counter when the registry address holds other code or none, or the code cannot be checked", "targets the registry recorded at deploy, with the code hash recorded there". Why not live: it needs other code at the registry's address, which only a redeploy could put there; every live run checks that code hash itself before its first attack.
- NOT RUN live: C22-upstream: an upstream redirect, a body over 1 MiB or not JSON, the 8-second timeout, and no client header forwarded. Proven by packages/server/test/proxy.test.ts: "refuses an upstream redirect without following it", "refuses an upstream body over 1 MiB and a body that is not JSON", "gives up after 8 seconds with 504", "forwards no request header: Cookie, Authorization and X-Forwarded-For stay behind". Why not live: the upstream is QoreChain's public REST, which this suite does not control and does not attack.
