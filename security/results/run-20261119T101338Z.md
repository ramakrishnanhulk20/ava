## C-numbers with no live attack here

- C11: fresh epoch keys are randomness inside @ava/core's newEpochKey; nothing outside can push on it or see it; core's tests cover the source.
- C14: one key and a fresh nonce per document happen inside encryptDocument; not observable from outside; core's tests cover it.
- C18, C19, C20, C21: browser invariants (stored identity, CSP, rendering, strangers' boards); the app is not built yet.
- C26: the browser treats a relay hash as a claim until the receipt; the app is not built yet.
- C31: showing state is shared needs two server instances or a restart of the dev server, which this suite does not control; C27-second-request and C43-replay show the once-only records hold across requests, and C31-cursor-cas above is proven by unit tests.
- C32: its proof is a grep of the built app's bundles, pages and server-component payload, which do not exist yet.
- C37: the demo chair's key is attacked through C33 (no signing oracle) and C36 (the drill key); its rotation step is the runbook's own dry run, which reads the demo chair's phrase and so stays outside this suite.
- C38, C39: the exposure ledger runs in the browser; not built yet.
